# bbrhm.github.io

Personal website: projects, demos and articles. Built with Eleventy, published on GitHub Pages. The output is static HTML and CSS, with inert JSON-LD metadata and a small local theme script. There is no framework, analytics or remote font dependency. The original list layout uses system sans-serif fonts, warm off-white/taupe neutrals and small green accents. Short CSS animations respect reduced-motion preferences.

## Local preview

Use Node 22 (Node 20.19+ also works).

```sh
npm ci
npm run dev
```

Open `http://localhost:8080`. Run `npm run check` before publishing. Generated files go in `_site/` and are not committed.

## Day and night mode

The sun/moon button beside the navigation switches appearance. New visitors follow their device setting; a manual choice is saved in `localStorage` under `bbrhm-theme` and restored before the stylesheet loads. Choices sync between open tabs. If storage is blocked, the switch still works for the current page. Without JavaScript, CSS follows the device setting and hides the inactive control.

`npm run check` includes theme behavior checks for saved preferences, switching, storage failures, device changes and cross-tab updates.

## Add or edit a project

Edit `src/_data/projects.json`. Entries appear in their listed order. Copy a small project icon into `src/assets/` and use its root-relative path. Use the public site or demo URL; the application source repositories are private.

## Add an article

Create `src/articles/article-slug.md`:

```markdown
---
title: Article title
description: A short summary.
date: 2026-11-02
draft: true
---

Start the article here. The layout supplies the title, date and summary.

## A section

Write in Markdown.
```

Change the date to the publication date and remove `draft: true` to publish. The filename sets the URL: `/articles/article-slug/`. The homepage, articles index, Atom feed and sitemap update automatically. Drafts and future-dated articles are excluded from the build. A future-dated article needs a new build on or after its date; there is no scheduled publishing job. Dates are interpreted in UTC.

For images, add files under `src/assets/` and use descriptive alt text. Keep the article filename stable after publication. There are no published articles initially.

Optional article front matter: `updated` records an actual revision date for search metadata, the sitemap and feed. `image` can specify a root-relative or HTTPS share image; add `imageAlt` and, if known, `imageWidth`/`imageHeight`. Without a custom image, links use the site's 1200 × 630 share card.

## Search and sharing

Page titles, descriptions, canonical URLs, Open Graph/Twitter cards and WebSite/Person/page JSON-LD are generated by `src/_data/eleventyComputed.js`. Published articles also receive author and publication/revision metadata. The 404 page is marked `noindex`. The sitemap, robots.txt and Atom feed remain automatic.

`src/assets/social-card.png` is the default preview for shared links. Regenerate it with `python3 scripts/create-social-card.py` using Pillow. Pass `--font /path/to/a/sans-serif.ttf` on systems without the default macOS Arial font. This is an optional authoring tool; deployment does not need Python or Pillow.

## Publish

The `Website` workflow checks pushes and pull requests. A push to `main` publishes after a successful build. Pull requests only build.

For the initial setup, go to [Settings → Pages](https://github.com/bbrhm/bbrhm.github.io/settings/pages) and select **GitHub Actions** as the source. Then run the [Website workflow](https://github.com/bbrhm/bbrhm.github.io/actions/workflows/pages.yml) if the first deployment ran before Pages was enabled. This needs to be done once.

## Files

- `src/_data/projects.json`: project listing.
- `src/articles/*.md`: articles.
- `src/_includes/`: shared page and article layouts.
- `src/assets/site.css`: styles and day/night palettes.
- `src/assets/theme.js`: the appearance switch and saved preference.
- `src/_data/site.json`: site details.
- `../bbrhm/README.md`: separate GitHub profile repository; keep project descriptions consistent.

Project icons are copied from their respective applications. No application source code is included here.
